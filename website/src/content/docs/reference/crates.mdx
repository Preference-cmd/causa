`cargo add causa@0.1.0` is the default entry for the 0.1.0 release. Cargo resolves the family dependencies for you; using the layer
crates directly is optional. All six version in lockstep at `0.x`, dual-licensed
`MIT OR Apache-2.0`.

## Roles

| crate | role |
| ----- | ---- |
| [`causa`](https://docs.rs/causa) | facade over the family |
| [`causa-kernel`](https://docs.rs/causa-kernel) | editable context material + contracts for models, preparation and tools, no I/O |
| [`causa-protocol`](https://docs.rs/causa-protocol) | request/response and incremental SSE translation (Anthropic / OpenAI Chat / OpenAI Responses) |
| [`causa-runtime`](https://docs.rs/causa-runtime) | optional material-returning turn runner, borrowed observations and bound tool execution |
| [`causa-provider`](https://docs.rs/causa-provider) | reqwest complete-response and streaming adapters for the `ModelGateway` port |
| [`causa-extension`](https://docs.rs/causa-extension) | extension adapters (`mcp` feature: MCP client) |

## Feature selection

| selection | gets |
| --------- | ---- |
| `causa = "0.1.0"` (default) | kernel + runtime + providers |
| `features = ["full"]` | + extensions (MCP) |
| `default-features = false` | kernel only (offline audit / minimal embed) |
| `default-features = false, features = ["runtime"]` | kernel + offline driver |

A provider renders through the protocol crate, so `providers` implies
`protocol` — you never enable a transport without its translation.
Extensions stay opt-in because `rmcp` is a heavier dependency that offline
hosts should not pay for.

The protocol and gateway options each crate exposes are listed in
[Protocol options](/reference/provider/protocol-options/).

Full API docs for every crate: [docs.rs/causa](https://docs.rs/causa)
(built with `all-features`).
