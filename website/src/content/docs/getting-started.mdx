## Add the dependency

The following dependency selections use the published **0.0.2 experimental
release**. The application example below uses the same registry version.

```bash
# Default: kernel + runtime + providers (Anthropic / OpenAI adapters).
cargo add causa@0.0.2

# Everything, including MCP extension adapters:
cargo add causa@0.0.2 --features full

# Kernel only — offline audit / minimal embed, no I/O:
cargo add causa@0.0.2 --no-default-features

# Kernel + offline driver, no network adapters:
cargo add causa@0.0.2 --no-default-features --features runtime
```

Choose one of the dependency configurations above. Causa requires Rust
**1.96+**; the async application below also adds Tokio.

## Run one turn in your application

Use Rust **1.96+** and create an application:

```bash
cargo new causa-hello
cd causa-hello
cargo add causa@0.0.2
cargo add tokio@1 --features macros,rt
```

Replace `src/main.rs` with the following. All Causa imports come through the
facade; this example asks a model one question without registering tools.

```rust
use causa::{
    kernel::{BlockContent, BlockMeta, CancellationToken, ContentPart, Context, ContextBlock,
             ModelRef, TextPayload, TurnId},
    providers::AnthropicMessagesGateway,
    runtime::{new_block_id, RunControl, ToolExecutor, ToolExecutorOptions,
              TurnResult, TurnRunOptions, TurnRunner},
};
use std::sync::Arc;

#[tokio::main(flavor = "current_thread")]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let gateway = Arc::new(AnthropicMessagesGateway::new(
        std::env::var("ANTHROPIC_API_KEY")?,
    ));
    let executor = Arc::new(ToolExecutor::new(Vec::new(), ToolExecutorOptions::default())?);
    let runner = TurnRunner::new(gateway, executor);
    let context = Context::from_blocks(vec![ContextBlock::new(
        new_block_id(),
        BlockContent::Parts(vec![ContentPart::Text(TextPayload::new("Say hello in one sentence."))]),
        BlockMeta { source: Some("user".into()), ..Default::default() },
    )])?;
    let options = TurnRunOptions::new(ModelRef::new(std::env::var("ANTHROPIC_MODEL")?));
    let outcome = runner
        .run(TurnId::new("hello"), context, options,
             RunControl::new(CancellationToken::new(), None))
        .await;
    match outcome.result {
        TurnResult::Completed { final_output } => println!("{}", final_output.response.text.0),
        result => return Err(format!("turn did not complete: {result:?}").into()),
    }
    Ok(())
}
```

Set `ANTHROPIC_API_KEY` in your environment and `ANTHROPIC_MODEL` to a model ID
available to your account, then run `cargo run`. This makes a real provider
request and requires network access.

## Run the repository examples

The `cargo run --example ... -p ...` commands on this site require the Causa
repository workspace. Adding `causa` to your application's dependencies does
not make those examples application targets. From a separate directory:

```bash
git clone https://github.com/Preference-cmd/causa.git
cd causa
```

The default checkout follows development. Run `git checkout v0.0.2` to use
this release's examples.

With `ANTHROPIC_API_KEY` already set, run this from the repository root:

```bash
cargo run --example quickstart -p causa-provider
```

The `quickstart` example adds a local `Tool` to a provider-backed turn. It lives
in `causa-provider`, which can use the runtime through a dev-dependency while
keeping the normal dependency graph layered.

## No API key? Run offline

From the same repository root, these examples use scripted stub gateways and
run with no network:

```bash
cargo run --example conversation_persistence -p causa-runtime
cargo run --example streaming_print -p causa-runtime
cargo run --example approval_processor -p causa-runtime
cargo run --example media_feedback -p causa-runtime
```

See [Examples](/examples/) for what each one demonstrates.
