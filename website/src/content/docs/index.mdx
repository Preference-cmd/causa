**Causa keeps an agent's conversation — messages, tool calls, tool results —
as a typed `Context` that your application holds.** Save it as JSON, edit
it, load it in another process. An optional runner calls the model and runs
the tools it asks for, then hands the context back. Nothing runs, retries
or saves unless your code asks: there is no harness.

## What Causa does, and what stays yours

<CardGrid>
  <Card title="In Causa" icon="seti:rust">
    - The `Context`: ordered and editable, with a stored form that holds
      across patch releases.
    - A turn runner with explicit limits, tool processors for approval, and
      an observer for logging.
    - Gateways for Anthropic Messages, OpenAI Chat Completions and OpenAI
      Responses, with streaming. Compatible servers are a base URL away.
    - MCP servers as tool sources.
  </Card>
  <Card title="In your application" icon="laptop">
    - History and storage: where conversations live and how long.
    - What the model sees each round, and what to drop when it grows.
    - Retries, timeouts and budgets.
    - Sessions, approval decisions and coordination between agents.
  </Card>
</CardGrid>

## Is it for you?

Causa fits a Rust application that wants to decide for itself how history,
storage and approval work, and needs a typed record of what the model saw and
did. It is the wrong choice if you want memory, planning or multi-agent
coordination ready-made, or need a tool's external effect to happen exactly
once across crashes. [Why Causa →](/why-causa/)

## Try it

Run a conversation offline, save it and load it again — no API key needed:

```bash
git clone https://github.com/Preference-cmd/causa.git
cd causa
cargo run --example conversation_persistence -p causa-runtime
```

Then add it to your project (Rust 1.96+) and run one turn against a model:

```bash
cargo add causa@0.1.0
```

## How it's built

<LayerDiagram />

Six crates share one version. The core (`causa-kernel`) does no I/O; the
runner, the gateways and the MCP adapter depend on it, never the other way
round, so each can be replaced. Depend on `causa` and choose the parts with
features. [Layering →](/concepts/layering/) ·
[Crates and features →](/reference/crates/)

## Learn by running

From the repository root:

- **Save and reload a conversation** — `cargo run --example conversation_persistence -p causa-runtime`
- **Stream a turn** as it arrives — `cargo run --example streaming_print -p causa-runtime`
- **Ask for approval** before a tool runs — `cargo run --example approval_processor -p causa-runtime`
