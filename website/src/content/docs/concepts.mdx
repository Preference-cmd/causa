## The kernel carries facts and contracts — nothing else

`causa-kernel` has no I/O, no transport, no policy. It holds:

- **Material** (`context`): `Context` owns ordered blocks and atomic edits;
  `ContextFrame` is an independent selection for a model request. Neither has a
  turn lifecycle or execution identity. Media uses durable `MediaRef` values;
  asset bytes live in the host's store.
- **Contracts** (`ports`): `ModelGateway`, `ContextPreparer`, `Tool`,
  `DynamicToolSource`, `ToolBatchProcessor`, `CallControl` and `ArtifactStore`.
  Third parties can implement or call these without adopting the runtime.

## Optional execution components

`TurnRunner` owns a gateway and `ToolExecutor`. Each call supplies a turn ID,
context, explicit model, options and control. It returns the editable context
on completion or controlled interruption, with the complete current tool batch
when results have not committed. Dropping the future or panicking bypasses that
return guarantee. Local cancellation cannot undo remote tool effects.

The runner binds the tool catalog before preparation, so the request surface and
execution targets refer to the same captured tool objects. An optional
`ContextPreparer` edits retained context and selects a request frame. The
request's logical invocation ID stays unchanged across gateway-owned retries.
Only declarations from a fresh model output become executable work; imported
context is never a resume command.

Tool processing applies ordered before processors, concurrent execution and
ordered after processors to one `ToolBatch`. A processor can await approval.
The executor collects started calls before returning a controlled interruption;
the runner commits results atomically only after successful processing and
validation. An unknown outcome is committed and stops further model rounds.

Six borrowed `RunEvent` observations expose requests, streaming deltas, complete
outputs, actual block appends and tool-processing entry/return. Observers choose
what to save; the runner keeps no implicit trace. Typed interruptions retain
failed conversion or commit inputs so an observer is not required for recovery.

History, session admission, input queues, budgets, model retries, output policies
and persistence belong to applications. Build preparation or processors from
those policies; no built-in session owner or budget strategy is imposed.

See [context editing](/context-editing/) for atomic replacement and append rules.

## Edge crates are adapters, not opinions

```text
kernel <- protocol <- provider
kernel <- runtime
kernel <- extension
(*, extension) <- causa (facade; depended on by none)
```

- `causa-protocol` — pure wire-protocol translation (Anthropic / OpenAI Chat /
  OpenAI Responses). No transport, no driver.
- `causa-provider` — reqwest `ModelGateway` adapters (implies protocol).
- `causa-extension` — `DynamicToolSource` adapters (`mcp` feature via the
  official `rmcp` SDK, client role only).
- `causa` — the facade. Kernel always on; defaults add the runtime components + providers,
  `full` adds extensions.

CI checks the family dependency directions and bans known transport packages
from the kernel. Keeping policy out of facts also requires API review.
Reference implementations of ports
(stores, counters, exporters) live in examples or hosts — never in the publish
set.
