## The kernel carries facts and contracts — nothing else

`causa-kernel` has no I/O, no transport, no policy. It holds:

- **Facts** (`context`): the conversation fact machine — blocks, turn state,
  deterministic projections. One logical message's mixed content commits as one
  fact block (`append_parts`); media travels as cheap durable `MediaRef`
  references whose bytes live only in the host's asset store.
- **Contracts** (`ports`): the seams third parties implement or call against —
  `ModelGateway`, `Tool`, `DynamicToolSource`, `ToolBatchProcessor`, `CallControl`, and
  `ArtifactStore`. A type lives in `ports` iff someone outside the kernel
  implements or calls it.

## causa-runtime is a set of optional components

`causa-runtime` holds the reference components you can adopt: the
execution stack (turn loop, tool-processing chains, dispatch, streaming), the
session aggregate (`ConversationState` / `ConversationStore`) and
session owner (`Session` / `SessionHandle`), and the policy
components (`FramePolicy`, `TokenCounter`, `TurnInteraction`).
`ConversationStore` is also a runtime contract; the kernel's `ArtifactStore`
is the separate port for tool artifacts. Everything is optional, and each piece is
offered as a reference: adopt it whole, or read it and build your own. What
adopting a piece brings along is documented as cost — not a promise about
how finely the crate can be split.

Key mechanisms:

- **Tool processing** — an ordered pre-processing chain, a fixed execution
  step and an ordered post-processing chain operate on one `ToolBatch`.
  A processor can await approval while holding the entire batch. Notes travel
  with each result and are visible to the model.
- **Interruption ownership** — an interrupted chain returns its current batch
  and cause. Your application decides what to do with that material; the runtime
  does not automatically retry, checkpoint or commit a partial batch.
- **Explicit output policy** — optional post processors control output limits
  and artifact storage. The processor changing content also maintains its
  truncation and artifact descriptions.
- **Identity** — opaque UUID block IDs identify declarations and results.
  Content keys serve optional batch-local deduplication; identical calls still
  have distinct declaration IDs and independent results.

## Edge crates are adapters, not opinions

```text
kernel <- protocol <- provider
kernel <- runtime
kernel <- extension
(*, extension) <- causa (facade; depended on by none)
```

- `causa-protocol` — pure wire-protocol translation (Anthropic / OpenAI Chat /
  OpenAI Responses). No transport, no driver.
- `causa-provider` — reqwest `ModelGateway` adapters (implies protocol).
- `causa-extension` — `DynamicToolSource` adapters (`mcp` feature via the
  official `rmcp` SDK, client role only).
- `causa` — the facade. Kernel always on; defaults add the runtime components + providers,
  `full` adds extensions.

CI checks the family dependency directions and bans known transport packages
from the kernel. Keeping policy out of facts also requires API review.
Reference implementations of ports
(stores, counters, exporters) live in examples or hosts — never in the publish
set.
