`cargo add causa@0.0.4` is the default entry for the 0.0.4 experimental
release. Cargo resolves the family dependencies for you; using the layer
crates directly is optional. All six version in lockstep at `0.x`, dual-licensed
`MIT OR Apache-2.0`.

## Roles

| crate | role |
| ----- | ---- |
| `causa` | facade over the family |
| `causa-kernel` | editable context material + contracts for models, preparation and tools, no I/O |
| `causa-protocol` | request/response and incremental SSE translation (Anthropic / OpenAI Chat / OpenAI Responses) |
| `causa-runtime` | optional material-returning turn runner, borrowed observations and bound tool execution |
| `causa-provider` | reqwest complete-response and streaming adapters for the `ModelGateway` port |
| `causa-extension` | extension adapters (`mcp` feature: MCP client) |

## Feature selection

| selection | gets |
| --------- | ---- |
| `causa = "0.0.4"` (default) | kernel + runtime + providers |
| `features = ["full"]` | + extensions (MCP) |
| `default-features = false` | kernel only (offline audit / minimal embed) |
| `default-features = false, features = ["runtime"]` | kernel + offline driver |

A provider renders through the protocol crate, so `providers` implies
`protocol` — you never enable a transport without its translation.
Extensions stay opt-in because `rmcp` is a heavier dependency that offline
hosts should not pay for.

The built-in gateways stream over real HTTP SSE; see [Streaming](/streaming/)
for the API and supported scope.

`GenerationOptions::reasoning_effort` is a string
sent as the host wrote it: OpenAI Chat `reasoning_effort`, Responses
`reasoning.effort`, Anthropic `output_config.effort`. Causa does not check or
map the value and derives no `thinking` object from it; omission keeps the
provider default. `GenerationOptions::extra_body` carries settings only one
protocol or model has, such as an Anthropic `thinking` object: it is merged into
the request, an object joining the object the adapter wrote under the same
key (`reasoning.summary` beside `reasoning.effort`) and any other value the
adapter wrote being kept. A value the provider refuses comes back as the provider's error. Output
limits render as `max_completion_tokens`, `max_output_tokens` and
`max_tokens`, and include reasoning tokens where counted. Anthropic requests
must set `max_tokens`; that adapter supplies no default.

Reasoning items that have to be echoed back are stored as sealed parts:
Anthropic `thinking` (with its signature) and `redacted_thinking`, Responses
`reasoning` items, and Chat `reasoning_content` are carried uninterpreted and
replayed verbatim by their own renderer. Responses requests send
`include: ["reasoning.encrypted_content"]` and `store: false` by default, and
each behaviour has a gateway option. Anthropic output schema requests are still
rejected.

Full API docs for every crate: [docs.rs/crate/causa](https://docs.rs/causa)
(built with `all-features`).

For contributors, CI checks dependency directions with all features enabled,
rejects `mod.rs` in library sources, and checks public API documentation.
From the repository root, run `bash .github/scripts/check-dependency-directions.sh`
and `python3 .github/scripts/check-module-layout.py`; see
[AGENTS.md](https://github.com/Preference-cmd/causa/blob/main/AGENTS.md)
for the full verification commands.

Public facade consumers are also checked independently of the workspace:

```bash
cargo test --manifest-path tests/consumers/material-flow/Cargo.toml --locked
cargo test --manifest-path tests/consumers/material-flow/Cargo.toml --features runtime --locked
cargo test --manifest-path tests/consumers/provider-streaming/Cargo.toml --locked
```
